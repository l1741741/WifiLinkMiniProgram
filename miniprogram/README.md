# 扫码连 WiFi · 微信小程序

配套的 H5 版本在仓库根目录（`public/`），这里是**小程序版**。

---

## 为什么做小程序版

H5 版本有一个绕不过去的限制：**浏览器不能调用系统 WiFi 接口**。
小程序能调 `wx.connectWifi`，但两个平台差别极大 —— 这是本项目的核心知识点：

| 平台 | 行为 | 结论 |
|---|---|---|
| **iOS** | `wx.connectWifi` 真·直连 | ✅ 一键连上 |
| **Android 10+** | 连上的 WiFi **只有小程序自己能用**，其他 App 上不了网 | ⚠️ 必须 `maunal:true` 跳系统设置页 |

安卓那条是微信官方文档原文写的，不是我们能绕过的：

> Android 微信客户端 7.0.22 以上版本，connectWifi 的实现在 Android 10 及以上的手机无法生效……
> 即连接上的 wifi 只对当前小程序有效，如果想要对整个系统生效，需要配置 `maunal` 来连接 wifi。

所以安卓上的实际流程是：小程序 → 跳系统设置页 → 手动点网络 → 粘贴密码 → 连接。
比 H5 只强在**跳转是原生的、不会被浏览器拦**。

**真正能同时解决"体验"和"广告"的是认证网关（Captive Portal）** —— 取消 WiFi 密码，
让顾客连上就是一步，网关在出口拦截并展示认证页。
如果以后能换路由器，那条路才是终点。详见根目录 README。

## 一个坑：Node 工具读不到 config.js

根目录 `package.json` 写了 `"type": "module"`，而 `miniprogram/` 下没有自己的
`package.json`，Node 会向上查找并继承这个设定，**把 `config.js` 当成 ES 模块**。

后果：用 `require('./config.js')` 拿到的是**空对象，而且不报错**。

- **小程序本身不受影响** —— 微信用自己的模块系统，走 CommonJS
- **但 Node 侧的工具会静默拿到空配置**

所以 `tools/check-miniprogram.mjs` 里是用 `new Function` 手动求值、
显式给 CommonJS 环境的，不是 `require`。如果你要写新工具读这个配置，照那个写法。

## 怎么跑起来

1. 装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
2. 「导入项目」→ 选择 `miniprogram/` 目录
3. AppID 填你自己的（或用「测试号」先跑通界面）
4. 编译

**开发者工具里连不上 WiFi** —— `platform` 会是 `devtools`，页面会走"复制密码 + 手动步骤"那条路。
真机预览才能测出两个平台的真实差异。

```bash
node tools/check-miniprogram.mjs    # 在仓库根目录跑，检查语法/页面完整性/事件绑定
```

## 配置（`config.js`）

### WiFi 信息

```js
wifi: {
  ssid: 'ChinaNet-3v9I-5G',
  password: '88888888',
}
```

### 广告

```js
ad: {
  adUnitId: '',                 // 流量主后台的激励视频广告位 ID
  placeholderWhenNoAd: false,   // ★ 默认 false = 没广告位时直接跳过广告页
  minSeconds: 5,
  skipAfterSeconds: 2,
  unlockOnError: true,          // ★ 广告挂了直接放行，别把顾客挡住
}
```

**`placeholderWhenNoAd` 为什么默认 false**：流量主要开通才有广告位，
在没开通之前，如果还让顾客等 5 秒倒计时，那是**拿真实转化率换一个没有任何收益的动画**。
默认直接跳过广告页进 WiFi 页。

### 连上之后去哪

```js
afterConnect: {
  webviewUrl: '',        // 跳自己的网页（需要先配置「业务域名」）
  miniProgram: null,     // 跳别的小程序：{ appId, path }
  customerService: false // 打开客服会话
}
```

顾客刚连上网、注意力在手机上，这是**整条链路上唯一的黄金引导时机**。
改成领券页或公众号引导，价值远高于放一段广告。

## 上线前必须知道的三件事

### ① 类目怎么选（这里我踩过坑，已经查清了）

**先说结论：不需要「设备管理」类目。**

网上很多教程（包括我上一版文档）会说“WiFi 接口需要设备管理类目，个人主体不可从事”，
**这个说法对你的场景是错的**。读完官方《硬件设备接入指引》后确认：

> **接入条件**：经过微信认证的非个人主体小程序。**面向智能硬件生产企业或开发者。**
>
> **接入步骤**：申请设备类目 → 开通硬件设备能力 → **添加设备类型** → 获取 **model_id**

它管的是「**用小程序去控制智能硬件**」（设备消息、音视频通话），
要求你是硬件厂商、要注册设备类型、要拿 model_id。
而“把店里 WiFi 密码告诉顾客”没有设备要注册，不是硬件厂商。

**而且我把整个服务类目文档搜了一遍：“WiFi”、“无线”、“网络服务”、“上网” 全部零匹配。**
微信根本没为这个场景设专门类目。

#### 所以该选什么

按**实际业务**选，不是硬塞进设备管理。推荐两个（资质要求栏都是空的，不需额外许可证）：

| 类目 | 官方适用范围原文 | 适合谁 |
|---|---|---|
| **工具 → 信息查询** | “适用于提供信息查询功能” | 最宽泛稳妥，兜底 |
| **商业服务 → 企业管理** | “适用于提供企业办公工具/办公管理、**门店信息管理、展示**等服务” | 服务方主体，描述直接命中 |

一个小程序最多申请 **5 个类目**，先报这两个，别一次报满。

#### 备案时比类目更关键的一条

> 单位备案选择类目应**符合单位经营范围**

这是管局的审核标准。所以：

- 营业执照有 **「网络技术服务」** —— 这是支撑网络工具类小程序的关键项
- 有 **「大数据服务」「人工智能应用软件开发」** 更是加分
- 备案备注里必须把业务和服务内容写清楚（模板见 `config.js` 的 `filing.note`）

### ② 流量主门槛（官方文档口径不一致）

- 页面文档写：累计独立访客 **UV ≥ 500**
- 接口错误码 `2013` 写：**1000 个独立访问用户**

**以你后台实际显示为准。** 这个门槛决定了你什么时候能有广告收入。

### ③ 小程序备案（不需要域名和网站）

备案走微信公众平台接口，前置条件是：名称/图标/描述填写完成、
至少一个审核通过的类目、非个人主体需微信认证、负责人人脸核身。

**不要求域名，不要求独立网站。** 所以这个方案不需要买域名、不需要买服务器。

> 唯一的例外：如果你想用 `afterConnect.webviewUrl` 跳网页，
> 那需要一个**已完成 ICP 备案的域名**并配置成「业务域名」。

### ④ 广告变现的边界（容易招审核问题）

| 做法 | 需要什么 |
|---|---|
| 用**微信流量主**（官方） | 只需 UV 达门槛，**不需额外类目** ✅ |
| 自己接**商家直客广告** | 可能被认定需要「广告」类目，甚至更严的资质 ⚠️ |

**建议：先用微信流量主，别一上来自己做广告位卖。**

## 已实现的细节（都是踩过的坑）

**平台分流**（`pages/wifi/index.js`）

- iOS 走 `wx.connectWifi` 真直连
- Android 走 `wx.connectWifi({ maunal: true })` 跳系统设置页
- 参数名就是**拼错的 `maunal`**，不是 `manual` —— 改了会静默失效
- 其他环境（开发者工具等）走复制密码 + 手动步骤

**iOS 的连接结果判定**

微信文档明说：iOS 不提供「密码错误导致连接失败」的事件。所以：

1. 监听 `onWifiConnected`，超时（12 秒）后再用 `getConnectedWifi` **实际核对**
2. 为什么超时后不能直接判失败：系统已经连着目标 WiFi 时再次连接，
   **永远返回成功且不触发 `onWifiConnected`** —— 只看事件会误判
3. SSID 比对时会去掉系统可能加的首尾引号

**安卓的位置权限**

安卓 6.0+ 把「扫描/连接 WiFi」归类为位置信息，必须先拿 `scope.userLocation`。
用户拒绝也放行 —— 让 `connectWifi` 自己去报错，比我们提前编一个错误准确。

**错误码翻译**

`12000`~`12014` 都翻译成了顾客能读懂的中文（见 `explainError()`）。
原始 `errMsg` 给顾客看等于没说。

**广告页不留在返回栈**

用 `wx.redirectTo` 而不是 `navigateTo` —— 否则顾客在 WiFi 页按返回会又回到广告页。

**跳转前先复制密码**

不管走哪条路，点「一键连接」时都先把密码写进剪贴板。
安卓跳设置页后要粘贴，iOS 失败时也能手动连。
